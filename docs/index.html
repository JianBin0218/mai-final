只用 K 個向量聽一段錄音，
模型還答得對嗎？

Qwen2-Audio 會把一段錄音變成數百個音訊向量交給語言模型。我們在中間放進一個瓶頸，把它們收成 K 個 latent，再請凍結的語言模型回答 yes/no 題。A 線研究容量 K 決定哪些聲音線索留得下來；B 線研究讓壓縮器先讀題目，能不能幫它挑對證據。

A 線　瓶頸容量　健賓 B 線　問題導引　cshsieh

同一台 GPU、同一批 340 題。K 為純音訊壓縮器（訓練 384 步），完整音訊與只看文字為原模型。刻度上的點也可以點選。

一動機與架構Motivation

回答端永遠不變，
我們只動壓縮端。

把數百個音訊向量收成固定的 K 個，就能直接量兩件事：留下多少資訊才夠用，以及先看題目能不能留對資訊。其他條件全部固定，所以分數的差異只來自壓縮端。

固定不動

凍結的 Qwen2-Audio

音訊編碼器、投影層、7B 語言模型都不訓練。回答端永遠讀到完整題目與 A/B 選項，只比較第一個輸出 token 是 A 還是 B。

A 線的變因

容量 K

K = 1、4、16 個 latent，加上免訓練的平均池化對照。看哪些題型最先因為容量不足而答錯。

B 線的變因

壓縮時讀不讀題目

題幹（不含選項）加進壓縮器的 query。換成錯置題、通用句或關閉，檢查效果是否來自題目內容。

五常見疑問Notes

幾個容易混淆的概念。

i.MLLM 是在推論時吃多模態，還是在「推理」時？

兩個說法指的是同一個過程。Qwen2-Audio 先用音訊編碼器把錄音轉成一串向量，投影到語言模型的 embedding 空間，再插進題目文字之間。之後語言模型就像處理一般 token 一樣，用同一套 Transformer 層一起處理聲音向量和文字。

所以多模態發生在輸入端：每次推論，模型都同時讀到聲音和文字，中間的運算不區分模態。在我們的專案裡，這個語言模型完全凍結，訓練時也不會改它。

ii.latent 是什麼？

這裡的 latent 指壓縮器輸出的 K 個向量。每個向量和語言模型的 token embedding 一樣是 4096 維，但不對應任何文字。它們被放在原本音訊 token 的位置，語言模型把它們當成 K 個「聲音 token」來讀。

原本一段錄音會給語言模型數百個音訊向量；瓶頸版只給 K 個（1、4 或 16）。每個 latent 等於「第 k 段的平均」加上「注意力挑出的修正」，A 線的置換實驗就是分別換掉這兩部分。

iii.為什麼可以有「只看音訊」的 latent？

壓縮器不需要知道題目也能工作。它有 K 個學出來的 query，每次都用同一組 query 去讀錄音，輸出這段錄音的摘要。

訓練時，回答端答錯的 loss 會傳回壓縮器，讓它學會保留大部分題目都用得到的資訊，就像不知道考題時，先把整段內容做成筆記。K 越小筆記越短，能保留的細節越少，這就是 A 線量的東西。

iv.推論時，模型看得到題目嗎？

回答端一直看得到。所有版本的語言模型都讀到完整題目和 A/B 選項。

差別只在壓縮端：純音訊版做筆記時看不到題目；題幹版做筆記時另外讀題幹（不含選項），想藉此只留下跟題目有關的聲音。B 線測的就是這一步有沒有用。

v.為什麼只比較 A、B 兩個 logit，不讓模型生成答案？

題目都是 yes/no，我們把選項寫成「A. yes / B. no」，只看第一個輸出 token 是 A 還是 B 的分數比較高。不需要解析生成的文字，評分完全確定，也能直接用 logit 差做分析。

vi.開發集和官方 test 怎麼分開？

fresh_val 是官方 validation 裡另外 170 段錄音、340 題，和 pilot 的訓練與驗證錄音互斥，每段一題 yes、一題 no。兩線都在這批題上報告，可以逐題比較。

A 線在固定樣本選取、題型與判讀規則後，才在 257 段官方 test 錄音上執行一次最終評估。
